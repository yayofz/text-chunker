# Text Chunker

Небольшой инструмент, который читает текстовый файл, режет его на куски с перекрытием, считает самые частые слова в каждом куске и умеет искать по предложениям. Есть HTTP API на FastAPI. Учебная заготовка под RAG-пайплайн.

## Что умеет

- Нарезка текста на куски по числу слов с настраиваемым перекрытием (`chunk_text`)
- Подсчёт частых слов с фильтрацией стоп-слов (`word_freq`, `top_words`)
- Поиск по предложениям без учёта регистра (`Document.search`)
- HTTP API для нарезки текста (`POST /chunks`)

## Требования

- Python 3.9+
- Для скрипта `main.py` сторонние библиотеки не нужны
- Для API нужны `fastapi` и `uvicorn`, они ставятся через `requirements.txt`

## Структура проекта

```
.
├── main.py             # класс Document и запуск скрипта
├── api.py              # FastAPI-приложение
├── utils.py            # chunk_text, word_freq, top_words
├── notes.txt           # входной текст для main.py
├── requirements.txt    # зависимости для API
└── README.md
```

## Запуск скрипта

```bash
python main.py
```

Рядом с `main.py` должен лежать файл `notes.txt` с текстом (UTF-8).

### Пример вывода

```
6
15
1 [('python', 3), ('язык', 1), ('программирования', 1)]
2 [('сложном', 1), ('синтаксисе', 1), ('последние', 1)]
3 [('ответ', 2), ('решает', 1), ('задачу', 1)]
4 [('работать', 2), ('базу', 1), ('или', 1)]
5 [('разбираться', 1), ('git', 1), ('виртуальных', 1)]
6 [('человек', 1), ('запоминает', 1), ('материал', 1)]
```

Первая строка: количество кусков. Вторая: число слов в последнем куске. Дальше: номер куска и три самых частых слова.

## API

### Запуск

```bash
pip install -r requirements.txt
uvicorn api:app --reload
```

Интерактивная документация, где можно пробовать запросы мышкой: http://127.0.0.1:8000/docs

### POST /chunks

Режет текст на куски с перекрытием.

Запрос:

```json
{"text": "a b c d e f g h i j", "size": 4, "overlap": 1}
```

Ответ:

```json
{"count": 3, "chunks": ["a b c d", "d e f g", "g h i j"]}
```

Поля `size` (по умолчанию 50) и `overlap` (по умолчанию 10) необязательны.

### Ошибки

Если `size` не больше 0, `overlap` отрицательный или `overlap >= size`, API вернёт `400` с описанием проблемы:

```json
{"detail": "overlap должен быть меньше size"}
```

## Возможные улучшения

- Docker-образ для запуска одной командой
- Эмбеддинги вместо частот слов: на коротких кусках частоты почти случайны

- Чтение пути к файлу и параметров нарезки из аргументов командной строки
- Тесты на `chunk_text` и `word_freq`
